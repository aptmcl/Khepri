Families

The family system is the most important part of using KhepriRevit effectively. Revit organizes all building elements into families — parametric templates that define an element's geometry, behavior, and available parameters. Khepri bridges this concept through set_backend_family, which maps Khepri's backend-agnostic families to Revit-specific family configurations.

Family Types Overview

Revit has three family types, each represented by a Khepri struct:

TypeStructUse CaseRevit Concept
System FamilyRevitSystemFamilyBuilt-in types: walls, slabs, roofs, floors, ceilings, pipesTypes defined by Revit itself — not loadable from files
File FamilyRevitFileFamilyLoadable .rfa files: columns, beams, windows, doors, furniture, fixturesLoadable families — .rfa files from Revit's library or custom-created
In-Place FamilyRevitInPlaceFamilyUnique project-specific elementsReserved for future use — not yet implemented

RevitSystemFamily

revit_system_family(family_map=(), instance_map=(), location_transform=(f, p)->p)

System families are Revit's built-in types. They cannot be loaded from external files — they are part of the Revit project template. Walls, slabs, roofs, ceilings, and railings are all system families.

Parameters

  • family_map: Pairs of "RevitParamName" => f -> expression that extract values from the Khepri family f to set Revit family type parameters. These define the type variant (e.g., wall thickness).

  • instance_map: Same format, but for instance parameters — values set per-placement rather than per-type.

  • location_transform: A function (family, position) -> adjusted_position that adjusts the placement coordinates. Used when Revit's insertion point convention differs from Khepri's (e.g., doors insert at center but Khepri specifies the edge).

How It Works

When a shape using a system family is realized:

  1. family_ref(b, family) calls backend_get_family_ref(b, family, rvtf)
  2. If the family type hasn't been resolved yet, the family_map parameters are collected and sent to Revit via FamilyElement(0, param_names, param_values) — the 0 signals a system family lookup
  3. Revit returns an ElementId for the resolved family type
  4. The result is cached in the parent Khepri family's ref::IdDict{Backend, Any} slot (generated by @deffamily) so subsequent calls reuse it

Example

The default door family shifts the insertion point by half the door width, because Revit expects doors positioned at their center:

set_backend_family(
  default_door_family(),
  revit,
  revit_system_family(
    [],   # no family_map
    [],   # no instance_map
    (f, p) -> p + vx(f.width/2, p.cs)))  # shift by half width

RevitFileFamily

revit_file_family(path, family_map=(), instance_map=(), location_transform=(f, p)->p)

File families are loaded from .rfa files — Revit's loadable family format. Columns, beams, windows, doors, furniture, and plumbing fixtures typically use file families.

Parameters

  • path: Absolute path to the .rfa file. Use revit_library_path to resolve paths relative to Revit's installed library.

  • family_map: Maps Revit type parameter names to functions that extract values from the Khepri family. These define the parametric dimensions of the family type (e.g., column width "b" and height "h").

  • instance_map: Maps Revit instance parameter names. Used when parameters are set per-placement (e.g., window "Width" and "Height").

  • location_transform: Adjusts placement coordinates, same as for system families.

Resolution Pipeline

When a shape using a file family is realized:

  1. family_ref(b, family) calls backend_get_family_ref(b, family, rvtf)
  2. The .rfa file is loaded via LoadFamily(rvtf.path) — Revit returns the family's ElementId
  3. A specific family type is created via FamilyElement(family_ref, param_names, param_values) using the family_map parameter mappings
  4. Revit creates (or finds) a type with those parameter values and returns its ElementId
Note

Family files are cached by their full normalized path inside the C# plugin (pathToFamily in Primitives.cs). The cache survives across multiple realizations within a single Revit session. Edit a .rfa mid-session and you must restart Revit for the change to take effect — the cache is not mtime-aware.

Example

The default column family loads a concrete rectangular column and maps Khepri's profile dimensions to Revit's "b" (width) and "h" (height) parameters:

set_backend_family(
  default_column_family(),
  revit,
  revit_file_family(
    revit_library_path("Metric Library",
      raw"Structural Columns\Concrete\M_Concrete-Rectangular-Column.rfa"),
    ["b" => f -> f.profile.dx, "h" => f -> f.profile.dy]))

Library Path Resolution

revit_library_path(root, path)

Resolves a path relative to Revit's installed content library. The root argument specifies which library branch to use.

Arguments

  • root: The library root — typically "Metric Library" or "Imperial Library".
  • path: The relative path within that library to the .rfa file.

Usage

# Metric column
revit_library_path("Metric Library",
  raw"Structural Columns\Concrete\M_Concrete-Rectangular-Column.rfa")

# Metric window
revit_library_path("Metric Library",
  raw"Windows\M_Instance-Window-Fixed.rfa")

# Imperial beam
revit_library_path("Imperial Library",
  raw"Structural Framing\Wood\Lumber.rfa")
Use raw strings for Windows paths

Always use raw"..." for the path argument to avoid backslash escaping issues. Without raw, \M or \S would be interpreted as escape sequences.

The function calls InstalledLibraryPath(root) on the connected Revit instance to get the actual library base path, then joins it with the relative path. This means paths adapt automatically to different Revit installations and versions.

Unit Conversion: to_feet and to_revit

The constant to_feet ≈ 3.28084 converts meters to feet. The helper to_revit(x) = x * to_feet is exported for use inside instance_map lambdas where the conversion must happen explicitly.

The key distinction:

  • family_map parameters flow through the C# RPC's Length parameter, which rLength() automatically multiplies by to_feet. Pass meters; the wire takes care of conversion. Do not call to_revit here.
  • instance_map parameters flow through the C# RPC's object[] values, which is decoded as raw doubles with no conversion. The Julia caller must pre-convert via to_revit(...).
# Column family_map: values in meters (no conversion — rLength handles it)
"b" => f -> f.profile.dx
"h" => f -> f.profile.dy

# Window instance_map: values in feet (explicit conversion)
"Width"  => f -> to_revit(f.width)
"Height" => f -> to_revit(f.height)
Tip

If a family parameter produces elements with incorrect dimensions, check whether the Revit parameter is shown in the Properties panel in display units (mm/m → use to_revit) or as a built-in Length (no conversion).

Multi-step Parameter Pattern

Some Revit families need their parameters set in two phases:

  1. Type-level parameters (the family_map) are baked into a duplicated FamilySymbol before the family instance is created. Two placements that request the same type-level values share a single duplicated symbol — i.e. they are the same Revit type. Use this for parameters that define the variant: profile dimensions, glazing pattern, structural material.
  2. Instance-level parameters (the instance_map) are applied per-placement after NewFamilyInstance via the C# SetParameters helper. Each placement gets its own value. Use this for parameters that vary per-occurrence: opening angle, sill height, mark, comments.

The canonical example is a circular window where the radius defines the type (two windows with the same radius can share a symbol) but the opening angle is per-instance (each window can be open by a different amount):

round_win = window_family(width=1.2, height=1.2)
set_backend_family(round_win, revit, revit_file_family(
  raw"C:\MyFamilies\ParametricRoundWindow.rfa",
  ["Radius"        => f -> to_revit(f.width/2)],   # type-level, baked
  ["Opening Angle" => f -> π/4]))                   # instance-level, per-placement

The revit_casement_window_family helper provides the same pattern with sensible defaults for the Metric library casement window:

casement = window_family(width=1.2, height=1.4)
set_backend_family(casement, revit, revit_casement_window_family(
  revit_library_path("Metric Library", raw"Windows\M_Casement-Double.rfa"),
  width=f -> to_revit(f.width),     # type-level Width
  sill =f -> to_revit(0.95)))       # instance-level Default Sill Height

When designing your own split:

  • A parameter is a good fit for family_map when changing it should produce a new logical type (a 600 mm column is "different" from a 700 mm column).
  • A parameter is a good fit for instance_map when two adjacent instances legitimately have different values (one window open, the next one shut).

Customization Examples

Changing the Default Column to a Steel I-Beam

set_backend_family(
  default_column_family(),
  revit,
  revit_file_family(
    revit_library_path("Metric Library",
      raw"Structural Columns\Steel\M_W-Wide Flange-Column.rfa"),
    ["bf" => f -> f.profile.dx, "d" => f -> f.profile.dy]))

Here "bf" (flange width) and "d" (depth) are the Revit parameter names for the W-shape family. You need to check the .rfa file's parameter names in Revit's Family Editor to find the correct names.

Using a Custom .rfa File for Windows

set_backend_family(
  default_window_family(),
  revit,
  revit_file_family(
    raw"C:\MyFamilies\Custom-Casement-Window.rfa",
    [],  # no family_map (type params)
    ["Width" => f -> f.width * to_feet, "Height" => f -> f.height * to_feet],
    (f, p) -> p + vx(f.width/2, p.cs)))

Custom .rfa files use an absolute path instead of revit_library_path.

Mapping Additional Parameters

To add flange width mapping to a beam family:

set_backend_family(
  default_beam_family(),
  revit,
  revit_file_family(
    revit_library_path("Metric Library",
      raw"Structural Framing\Steel\M_W-Wide Flange.rfa"),
    ["bf" => f -> f.profile.dx,    # flange width
     "d"  => f -> f.profile.dy,    # depth
     "tf" => f -> 0.015,           # flange thickness (fixed)
     "tw" => f -> 0.010]))         # web thickness (fixed)

Creating a Per-Element Family Override

You can override the family for individual elements:

# Define a specific column family
steel_col = column_family(profile=rectangular_profile(0.3, 0.3))
set_backend_family(steel_col, revit, revit_file_family(
  revit_library_path("Metric Library",
    raw"Structural Columns\Steel\M_W-Wide Flange-Column.rfa"),
  ["bf" => f -> f.profile.dx, "d" => f -> f.profile.dy]))

# Use it for specific columns
column(xy(0, 0), family=steel_col)
column(xy(5, 0), family=steel_col)

# Other columns still use the default
column(xy(10, 0))  # uses default_column_family()

Finding Revit Parameter Names

To customize family mappings, you need to know the Revit parameter names for your .rfa file. There are several ways to find them:

  1. Revit Family Editor: Open the .rfa file → Family Types dialog → lists all parameters with their names
  2. Revit Properties Panel: Place an instance → select it → the Properties panel shows instance and type parameters
  3. Revit API: Use Element.Parameters to enumerate programmatically

The parameter names used in family_map and instance_map must match exactly (case-sensitive) the names shown in Revit.
